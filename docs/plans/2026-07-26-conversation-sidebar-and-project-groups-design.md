# 会话侧边栏、多机器汇总与项目分组设计

日期：2026-07-26  
状态：需求确认稿

## 背景

当前移动端把会话列表和对话详情作为两个互斥页面展示。用户需要先返回列表，
再选择另一条会话，操作路径较长；多台机器同时在线时，还需要先切换机器才能找到
目标会话。

本次改版把会话列表改为常驻于应用结构中的侧边栏，并补充跨机器汇总、单机项目
分组、新聊天机器/项目选择、上下文状态和会话操作入口。

## 目标

- 会话列表与对话详情处于同一个应用壳层，不再作为两个独立页面切换。
- 首次进入默认打开会话侧边栏，选择会话后一次点击进入详情。
- 保留现有机器 Tab，并始终在最前面显示“全部”。
- “全部”汇总所有机器的会话，具体机器按项目分组。
- 新聊天明确选择目标机器和项目，避免在错误机器或目录中启动任务。
- 保留现有在线、运行中、审批等设备状态语义。
- 保留对话详情的上下文占用和会话操作能力。
- 提高列表信息密度，不依赖卡片或横向分隔线划分内容。

## 非目标

- 不改变多后端的网络拓扑、连接池和鉴权方式。
- 不增加新的会话内容缓存；线程、Turn 和消息仍以 app-server 为来源。
- 不改变消息正文、工具调用、审批、Diff、模型和权限选择的既有行为。
- 不增加“工作区 / 工作树”模式。
- 不在本次设计中引入自动发现机器、云同步或公网访问。

## 总体信息架构

```text
应用壳层
├── 会话侧边栏
│   ├── 全部机器视图
│   ├── 单台机器视图
│   │   └── 按项目分组
│   ├── 搜索
│   └── 新聊天
└── 主内容区
    ├── 对话详情
    │   ├── 上下文状态
    │   └── 会话操作
    └── 新聊天
        ├── 机器选择
        └── 项目选择
```

会话侧边栏始终挂载在应用壳层中。“收起侧边栏”表示隐藏其可视区域，而不是卸载
列表或切换到另一套页面状态。

## 页面与状态

### 1. 会话侧边栏：全部

机器 Tab 最前面显示“全部”。“全部”视图用于快速找到
最近会话：

- 汇总所有已启用机器返回的会话。
- 有置顶会话时，在“最近”上方显示独立的“置顶”分组；没有置顶会话时隐藏该分组。
- “置顶”分组汇总所有机器的置顶会话，组内按 `updatedAt` 降序排列，缺失时回退到
  `createdAt`。
- 置顶会话只出现在“置顶”分组，不在“最近”中重复展示。
- “最近”不按项目分组，按 `updatedAt` 降序排列；缺失时回退到 `createdAt`。
- 每条会话使用两行紧凑布局：
  - 第一行：会话标题；右侧显示相对时间或运行状态。
  - 第二行：绿色来源圆点、机器名和项目名，例如
    `Mac mini · codex-web-mobile`。
- 不使用会话卡片和横向分隔线，仅通过字号、字重和紧凑留白建立层级。

如果只有一台机器，也显示“全部”，并展示该机器的全部会话。

### 2. 会话侧边栏：单台机器

选择具体机器后，只显示该机器的会话，并按项目分组：

- 项目名默认取线程 `cwd` 的最后一级目录名。
- `cwd` 为空或无法识别时归入“未识别项目”。
- 项目组按组内最近一条会话的更新时间降序排列。
- 组内会话按更新时间降序排列。
- 项目标题显示文件夹图标、项目名和会话数量。
- 项目组默认展开，首版不增加折叠操作。
- 会话行只显示标题和右侧时间或运行状态。
- 不重复显示机器名和项目名。
- 项目之间、会话之间均不使用横向分隔线。

### 3. 对话详情

侧边栏收起后，对话详情占满可用宽度：

- 左上角使用侧边栏菜单按钮，不再使用返回列表箭头。
- 标题区显示会话标题。
- 副标题显示绿色连接状态、机器名、项目名和连接状态。
- 正文时间线、模型/权限胶囊和输入框沿用现有逻辑。
- 右上角保留两个独立入口：
  - 上下文占用按钮：灰色静态环形容量指示。
  - 会话操作按钮：垂直三点图标。

灰色上下文容量环和蓝色运行中 Loading 表达不同含义，不得混用。

### 4. 新聊天

新聊天页在顶部直接展示两个可点击选择项：

- 项目：文件夹图标、项目名和下拉箭头。
- 机器：设备图标、机器名和下拉箭头。

不显示“工作区 / 工作树”选项。项目选择直接决定新线程的工作目录。

默认值规则：

- 从“全部”进入：恢复上一次新建聊天使用的机器和项目。
- 从具体机器 Tab 进入：自动选择该机器，并恢复该机器上次使用的项目。
- 切换机器后：只展示目标机器可用的项目；原项目不属于新机器时必须重新选择。
- 机器或项目无效时：发送按钮不可启动新线程，并给出明确提示。

项目候选优先来自该机器最近线程的 `cwd`，按最近使用时间排序并去重。后续如果
app-server 提供正式项目列表，应替换候选来源，不在前端维护第二套项目事实。

### 5. 上下文状态

点击详情页右上角的灰色环形按钮，打开底部状态面板。面板包含：

- 对话线程 ID，并提供复制按钮。
- 当前工作目录。
- 上下文剩余比例、已用量和总量。
- 7 天使用限制的剩余比例和重置时间。

面板规则：

- 采用底部 Sheet，包含拖动条、标题“状态”和关闭按钮。
- 背景对话内容轻度变暗，但保持当前位置。
- 字段使用紧凑双列布局，不使用横向分隔线。
- 线程 ID 和目录允许换行，不水平撑破页面。
- 上下文环显示“已使用比例”，面板文字显示“剩余比例”，两者必须由同一份数据
  推导，避免数值含义相反。
- 没有用量数据时显示“暂无数据”，不得伪造百分比。

### 6. 会话操作

点击详情页右上角的三点按钮，在标题区域下方打开锚定式操作面板：

- 顶部显示当前会话标题或首条内容的两行预览。
- 操作项：
  - 置顶。
  - 复制会话 ID。
  - 重命名。
  - 归档。
- “归档”使用红色危险色，其他操作使用中性色。
- 操作项之间不使用横向分隔线，通过图标、对齐和垂直留白区分。
- 点击面板外部、再次点击三点按钮或完成操作后关闭面板。

协议和状态边界：

- 复制会话 ID：使用浏览器剪贴板，不发送 app-server 请求。
- 重命名：使用 app-server `thread/name/set`。
- 归档：使用 app-server `thread/archive`；成功后从当前列表移除并关闭详情。
- 置顶和取消置顶：使用 app-server `thread/metadata/update` 更新持久化字段
  `isPinned`，成功响应返回刷新后的线程。

#### 置顶与取消置顶

点击“置顶”后的行为：

1. 根据当前会话的 `backendId` 找到来源机器的 `AppServerClient`。
2. 禁用当前操作项，并在操作项内显示中性色小型 Loading，防止重复提交。
3. 调用 `thread/metadata/update`：

   ```json
   {
     "threadId": "<当前会话 ID>",
     "isPinned": true
   }
   ```

4. 成功后使用响应中的最新线程覆盖对应机器列表中的线程数据。
5. 操作项文字变为“取消置顶”，关闭操作面板，并提示“已置顶”。
6. 如果当前列表处于“全部”Tab，该会话立即移动到顶部的“置顶”分组，并从“最近”
   分组移除。

点击“取消置顶”时调用相同方法并传入 `isPinned: false`。成功后：

- 从“全部”的“置顶”分组移除。
- 回到“全部”的“最近”分组，并按原 `updatedAt` 插入正确位置；取消置顶本身不得
  修改会话更新时间。
- 操作项恢复为“置顶”，提示“已取消置顶”。
- 最后一条置顶会话被取消后，隐藏空的“置顶”分组标题。

具体机器 Tab 保持原有结构和顺序：

- 始终按项目分组，不新增“置顶”分组。
- 置顶或取消置顶不改变项目顺序和组内时间顺序。
- 会话仍留在原项目下，不因置顶移动位置，也不重复展示。
- 操作面板根据线程的 `isPinned` 显示“置顶”或“取消置顶”。

加载和异常规则：

- 置顶请求的 Loading 只表示操作提交中，不使用蓝色运行任务 Loading。
- 请求成功前不提前改变分组，避免网络失败造成列表跳动后再回滚。
- 请求失败时保持原位置和原操作文案，重新启用操作项，并提示“置顶失败，请重试”
  或“取消置顶失败，请重试”。
- 一台机器请求失败不得影响其他机器的置顶状态或列表。
- 页面刷新或重新连接后，以 `thread/list` 返回的 `Thread.isPinned` 为准，不在前端
  维护第二套置顶持久化状态。
- 置顶能力要求来源机器的 app-server 同时支持
  `thread/metadata/update.isPinned` 和 `Thread.isPinned`。客户端必须校验成功响应中的
  `isPinned` 是否等于目标值；旧版服务忽略该字段时按失败处理并提示升级，不得显示
  虚假的“已置顶”。

## 侧边栏交互

### 打开与关闭

- 首次进入应用时默认打开侧边栏。
- 侧边栏覆盖屏幕约 85%，右侧保留约 15% 的当前详情预览。
- 右侧预览轻度变暗，用于提示其仍是可返回的主内容。
- 点击会话后自动收起侧边栏并打开对应详情。
- 点击右侧露出的详情区域可直接收起侧边栏。
- 详情页点击左上角菜单按钮可重新打开。
- 支持从屏幕左边缘向右滑打开。
- 浏览器返回键在侧边栏打开时优先关闭侧边栏，不直接离开当前会话。

### 状态保留

侧边栏关闭时保留：

- 当前机器 Tab。
- 搜索词。
- 列表滚动位置。
- 各项目组的展示状态。
- 当前选中的会话。

重新打开侧边栏时不得重新跳回列表顶部，也不得清空搜索。

## 机器 Tab 与状态

机器 Tab 保留现有状态语义：

- 绿色圆点：机器在线。
- 蓝色小转圈：该机器存在运行中的会话。
- 待审批数量：该机器存在待处理审批。
- 离线或重连：沿用现有错误和重连状态。

“全部”本身不代表独立后端，不建立额外 WebSocket。它只是对各机器运行状态和线程
列表的前端派生视图。

点击机器 Tab 只改变列表过滤范围，不关闭其他机器连接，也不取消其他机器上的
运行任务。

## 运行中状态

运行中的会话沿用现有视觉逻辑：

- 不显示“进行中”文字。
- 会话行右侧显示蓝色实心圆点和蓝色开口圆环 Loading。
- Loading 持续旋转。
- 对应机器 Tab 同时显示较小的蓝色转圈提示。
- 绿色圆点仍表示连接在线，不应被蓝色 Loading 替换。
- Turn 完成后移除 Loading，恢复相对时间。

“全部”视图必须把运行事件归属到正确机器；单台机器视图只响应该机器自己的事件。

## 搜索逻辑

- “全部”Tab：搜索所有机器的会话标题、机器名和项目名。
- 具体机器 Tab：只搜索该机器的会话标题和项目名。
- 搜索结果继续遵守当前视图的排序和分组规则。
- 单机视图中过滤后没有会话的项目组不显示。
- 没有结果时显示“没有匹配的对话”，不清空搜索框。

## 数据派生

跨机器列表需要在 UI 层构造统一展示模型，但不得复制或持久化线程内容：

```ts
interface AggregatedThreadItem {
  backendId: string;
  backendName: string;
  threadId: string;
  title: string;
  cwd: string | null;
  projectName: string;
  updatedAt: number;
  createdAt: number;
  running: boolean;
  pinned: boolean;
  thread: Thread;
}
```

数据流：

```text
各 BackendRuntime.threads
→ 附加 backendId / backendName
→ 从 cwd 派生 projectName
→ 合并为全部机器列表
→ 按 Thread.isPinned 拆分“置顶”与“最近”
→ 各分组应用时间排序和搜索
→ 渲染全部视图

选中某台机器
→ 过滤 backendId
→ 按 projectName 分组
→ 项目组按最新活动排序
→ 组内按时间排序
→ 渲染单机视图
```

打开“全部”中的会话时，必须同时切换当前后端上下文和线程：

1. 根据列表项的 `backendId` 定位来源 `BackendRuntime`。
2. 将详情绑定到来源后端的 `AppServerClient`。
3. 调用该后端的线程恢复逻辑。
4. 成功进入加载态后收起侧边栏。
5. 后续 Turn、审批、模型、权限和错误都继续归属于该后端。

不得把一台机器的线程交给另一台机器的客户端恢复。

## 新聊天数据流

```text
点击“新聊天”
→ 根据入口确定默认机器
→ 读取该机器最近项目
→ 用户确认或修改机器和项目
→ 选择模型与权限
→ 首次发送
→ 使用目标机器的 AppServerClient 调用 thread/start
→ cwd 使用所选项目完整路径
→ 创建成功后进入新会话详情
```

机器切换必须同步更新项目选择，草稿文字和待发送图片可以保留，但在发送前必须再次
确认目标机器和项目仍有效。

## 加载、错误与空状态

- “全部”初次加载：各机器可以独立完成；已加载机器先显示，不等待最慢机器。
- 单台机器加载失败：只在对应 Tab 标记错误，不清空其他机器结果。
- “全部”中存在部分失败：展示可用结果，并提示哪些机器不可用。
- 会话详情加载：沿用现有骨架屏和重试逻辑。
- 项目列表为空：显示“没有可用项目”，并阻止启动新线程。
- 线程被归档或外部删除：关闭对应详情，从列表移除并提示状态变化。
- 重命名成功：列表标题和详情标题同步更新。
- 运行事件晚到：必须根据 `backendId`、`threadId` 和连接 `generation` 判断归属。

## 视觉规范

- 侧边栏整体保持高信息密度，但所有可点击控件至少有 44px 触控区域。
- 会话标题优先单行省略，不能挤压右侧时间或 Loading。
- “全部”的来源信息使用次级字号和灰色文本。
- 单机项目标题的视觉权重大于组内会话，但弱于页面标题和机器 Tab。
- 列表、项目组和操作面板不使用横向分隔线。
- 不使用大面积阴影或彩色卡片；阴影只用于区分侧边栏、Sheet 和锚定面板。
- 在线绿、运行蓝、危险红各自只表达一种含义。

## 当前实现影响

当前 `BackendWorkspace` 以 `active` 是否存在决定渲染 `ThreadListPage` 或
`ConversationPage`。本设计需要改为两者同时位于应用壳层，由侧边栏可见状态控制
布局。

现有每台机器仍维护独立运行状态。本设计在这些状态之上增加只读聚合层，不把多个
`AppServerClient` 合并成一个客户端。

当前代码尚未包含完整的上下文状态面板和会话操作面板。实现时应优先复用 app-server
已经提供的线程命名、归档和 token usage 能力，不在网关新增第二套业务 API。

## 验收标准

### 列表与侧边栏

- 无论机器数量，“全部”Tab 都始终显示。
- “全部”能按时间展示所有机器的会话，并显示机器和项目来源。
- “全部”存在置顶会话时显示独立的“置顶”分组，且置顶会话不在“最近”重复出现。
- 具体机器按项目分组，行内不重复机器和项目。
- 具体机器 Tab 不增加“置顶”分组，置顶操作不改变项目和会话排序。
- 两种视图均无横向分隔线，信息密度符合移动端长列表使用。
- 运行会话和机器 Tab 均显示正确的蓝色旋转 Loading。
