# 会话详情即时进入与骨架屏设计

## 背景

当前 `openThread` 会先等待 `thread/resume` 返回，再通过 `setActive` 进入详情页。
当历史较长或网络较慢时，用户点击会话后仍停留在列表，容易误以为点击无效。

## 目标

- 点击会话后立即进入详情页。
- 详情头部立即显示列表已有的标题和工作目录。
- 完整会话返回前，时间线显示骨架屏。
- 加载完成后用真实消息替换骨架屏，并定位到最新内容。
- 加载失败时停留在详情页，显示错误和“重试”按钮。
- 加载中返回列表或改开其他会话时，迟到响应不得改变当前页面。

## 状态设计

在每个后端工作区中增加独立的详情加载状态：

```ts
type ConversationLoadState = "idle" | "loading" | "ready" | "error";
```

- `idle`：当前不在已存在会话的详情加载流程中。
- `loading`：已进入详情，正在等待 `thread/resume`。
- `ready`：完整会话已经加载，可以发送消息和调整设置。
- `error`：加载失败，保留当前会话摘要并允许重试。

加载错误使用详情专用字段保存，不复用连接级 `error`，避免一次会话读取失败把整个
设备标记为异常。

## 数据流

### 首次打开

1. 用户点击列表项。
2. 递增 `openSequenceRef`，使旧请求失效。
3. 立即将列表项摘要设为 `active`，清空草稿并设置 `loading`。
4. `ConversationPage` 立即渲染头部和时间线骨架屏；编辑器保持可见但不可操作。
5. 后台调用 `thread/resume`，必要时继续使用现有的 `thread/read` 回退。
6. 仅当请求序号仍是最新值时，写入完整线程、模型与权限设置并切换为 `ready`。

### 失败与重试

失败后保留 `active` 摘要，切换为 `error`。时间线显示错误说明和“重试”按钮；
头部返回按钮始终可用。点击重试会生成新的请求序号，重新进入 `loading`，成功后
进入 `ready`。

### 取消和竞态

- 返回列表时递增 `openSequenceRef`、清空详情状态，再将 `active` 设为 `null`。
- 连续打开不同会话时，只有最后一次请求可以更新界面。
- 断线重连恢复当前会话成功后，同步清除详情错误并进入 `ready`。

## 组件职责

`BackendWorkspace` 负责：

- 管理详情加载状态和错误。
- 立即切换页面。
- 发起、取消和重试加载。
- 在完整数据返回后同步会话设置。

`ConversationPage` 负责：

- 根据加载状态显示骨架屏、错误重试区或真实时间线。
- 在未进入 `ready` 前禁用编辑器及设置入口。
- 保持头部和返回操作始终可用。

## 骨架屏

骨架屏放在时间线区域，使用数个不同宽度的圆角块模拟用户消息、AI 文本和工具摘要。
动画沿用列表骨架屏的弱脉冲效果，并遵守 `prefers-reduced-motion`。

## 测试

先增加失败测试，再实现：

1. 延迟 `thread/resume` 时，点击后立即显示详情头部和骨架屏。
2. 数据返回后骨架屏消失并显示真实消息。
3. 加载失败时留在详情页并显示重试入口。
4. 重试成功后显示完整会话。
5. 加载中返回列表后，迟到响应不会重新打开详情。
6. 连续打开不同会话时，旧响应不能覆盖新会话。
