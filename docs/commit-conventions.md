# Git 提交规范

本仓库采用 Conventional Commits（约定式提交），使用英文类型标识变更类别，使用中文描述具体内容。

## 提交格式

```text
<类型>(<可选范围>): <中文标题>

新增功能：
- ...

主要修改：
- ...
```

要求：

- 标题必须使用中文描述，类型和可选范围除外。
- 标题应简洁、准确，不使用句号结尾。
- 正文必须包含“新增功能”和“主要修改”两个部分。
- 没有新增功能时，在“新增功能”下填写“无”。
- 每个提交只包含一个明确目的，不混入无关修改。

## 提交类型

| 类型 | 使用场景 |
| --- | --- |
| `feat` | 新增用户可见功能 |
| `fix` | 修复缺陷或错误行为 |
| `ci` | 修改 CI/CD、GitHub Actions 或发布流程 |
| `docs` | 仅修改文档 |
| `test` | 新增或调整测试 |
| `refactor` | 重构代码，但不改变现有功能 |
| `perf` | 性能优化 |
| `style` | 不影响逻辑的格式或视觉样式调整 |
| `build` | 修改构建系统、打包方式或依赖 |
| `chore` | 其他维护性修改 |
| `revert` | 撤销已有提交 |

## 范围

范围用于标明主要影响区域，可以省略。推荐使用简短、稳定的中文名称，例如：

```text
feat(远程文件): 支持 Markdown 预览与源码切换
fix(引导消息): 修复悬浮副本未及时消失
ci(发布): npm 失败时继续发布移动端应用
```

## 正文

正文需要说明用户获得了什么能力，以及代码具体做了哪些调整。

```text
feat(远程文件): 支持 Markdown 预览与源码切换

新增功能：
- 远程 Markdown 文件默认使用渲染模式预览
- 支持在预览与源码模式之间切换

主要修改：
- 复用现有 Markdown 渲染器
- 保留源码行号和目标行高亮
- 增加远程 Markdown 文件回归测试
```

纯修复、文档或 CI 修改没有新增功能时：

```text
fix(引导消息): 修复悬浮副本未及时消失

新增功能：
- 无

主要修改：
- 使用 app-server 的 clientId 关联引导请求
- 在线程恢复后重新对账引导消息状态
- 增加实时事件和断线恢复测试
```

## 不兼容变更

不兼容修改需要在类型或范围后添加 `!`，并在正文末尾说明影响：

```text
feat(配置)!: 调整设备连接配置格式

新增功能：
- 支持在网关地址中直接携带访问口令

主要修改：
- 合并网关地址与访问口令输入
- 移除旧版独立口令字段

BREAKING CHANGE: 旧版设备配置需要重新保存后才能继续使用。
```

## 提交前检查

提交前至少确认：

```bash
git diff --check
git diff --cached --check
git diff --cached --name-status
```

提交信息必须基于实际暂存内容编写，不得描述未包含在本次提交中的功能。
